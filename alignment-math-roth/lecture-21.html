2Overview

All right. Today I want to think about auditing, or testing. Imagine that there is some phenomenon that you would like to predict. You don't know the physical process underlying this phenomenon. Think about, I don't know, weather on Pluto, or you're trying to predict some […] event. The point is, what you're going to get to observe is a sequence of probabilistic forecasts that say things like "I think there's a 2% chance that the event happens today," followed by a realization of whether the event actually happened today or not.

And you've got this forecasting technology that is feeding you these forecasts, but what you're trying to audit for is whether this forecasting technology actually understands the underlying physical process governing the probabilistic nature of these events: whether it is actually telling you the true conditional outcome probability given everything it has, or whether instead it's somehow doing something that is just trying to fool you into thinking that it knows the underlying ground truth.

So you're trying to distinguish, on the one hand, a fully informed forecaster that knows every day the true conditional label probabilities and tells them to you honestly. On the other hand, maybe a charlatan, a completely uninformed forecaster that knows the test it's trying to pass, that knows how you're auditing it, but otherwise knows nothing at all about the underlying physical process. And the question is, to what extent can we design tests that have some distinguishing power, that have some ability to tell the difference between a forecasting technology that is correct versus one that is just trying to game the task?

3Calibration Does Not Certify Knowledge

So just to remind ourselves of some things we know: what kind of test can we envision? The kind of things we see are probabilistic forecasts. Someone says, "I think there's a 23% chance of rain tomorrow," followed by realized outcomes, […]. And we see this over some sequence.

And so one kind of test you could imagine is this thing we studied at some length in this class, a calibration test: that on the days when you predicted a 50% chance of rain, on average it rained about 50% of the time. But we've already seen that calibration tests alone are not enough to certify that you know what you're talking about. It's possible to make calibrated forecasts that don't capture the underlying generative process of the model and that nevertheless pass calibration.

So just to go back to the simplest example from when we were studying calibration: suppose the thing you're trying to forecast just occurs deterministically on even days, and it doesn't occur on odd days. So it's 0, 1, 0, 1, 0, 1. An informed forecaster would forecast a 0% chance of the event on odd days and a 100% chance of the event on even days. But if I just forecast a 50% chance of the event every day, that ends up being perfectly calibrated.

Okay, so it means that if your hope was to distinguish whether I know what I'm talking about or not by subjecting me to some ex-post test of my forecasts and the realized outcomes, calibration is not going to be a sufficiently strong test. It doesn't have the distinguishing power. Not only are there uninformed forecasts that pass the calibration test on this example, the fact that we gave these algorithms based on Blackwell approachability that can pass a calibration test on every single example means that if I know that the way you're going to evaluate me is through a calibration test, I can essentially game the test. I can pass the test without needing to learn anything at all about the underlying probabilistic process.

So if the thing we want to do is audit predictive technologies, if we want to have some tests that can distinguish, say, technologies that have an underlying mechanistic understanding of the world from those that don't, can we do it via some other means? Maybe the calibration test was too naive, but maybe we can find a different test that would [suffice].

4A Rule Gives a Forecast After Every History

Okay, so here's going to be the model. As in the online calibration setting, what we get to do is inspect the algorithm we're given. We get to inspect the model we've been given that makes forecasts. And then we can observe what happens over some sequence of \(T\) days. So every day we get to observe: did the outcome occur or not? And I'll talk about this in a world in which there's no context, but contexts don't change anything I'm saying. There could be features that I observe every day as well as the outcome, and that's not going to change anything we talk about.

And a forecasting rule is going to be, think of it as some machine learning model that we can query on arbitrary histories. It's like we have access, say, to the model weights. So we can query this model not just on the sequence of outcomes that has actually occurred, but we've got more power than that. We can query it on alternative histories that never happened, or query it on histories that haven't happened yet. And for any history, we can query it, and it will tell us what it would predict in that scenario. It would tell us what probability of the event it would predict after any particular history we've given it.

So a calibration test, for example, doesn't use this additional power. A calibration test just looks at the sequence of predictions it actually made along the realized history and the sequence of outcomes that we've observed. But once you publish an LLM, or here a forecasting rule, that does allow you more power: you can query it not just on the history that actually resulted but on other histories as well. I'm going to allow that as part of the family of tests we're talking about.

Okay, so the forecasting rule specifies for any history what the probability is of the outcome at the next round, and if we had features, it could specify that as a function of the features as well as the history. In particular, it makes a sequence of forecasts along the realized history of outcomes.

And what it would mean for a forecasting technology to know the true underlying process is that there was some arbitrary joint distribution on sequences of outcomes (with features, it could be sequences of outcomes cross features). And that joint distribution would, for any history, and if we had features, given tomorrow's features as well, induce some correct conditional expectation for the probability that the event occurred the next day, given the history.

And our testing goal is, given a published model and given a single observed sequence of outcomes realized through time, to be able to determine whether the published model is the informed model. We don't know what the true underlying probabilistic process is. If we knew that, we wouldn't need a model. We only get to observe sequences of outcomes, but we get to observe the full forecasting model. And the testing problem is whether the forecasting rule is equal to the informed forecasting rule or not. Is this thing telling us the truth, or is it somehow trying to game your test?

6The Provider Can Choose Its Forecaster by Coin Flip

Okay, so how do we think about things like online calibration algorithms? I've said that the test is allowed to inspect the forecasting algorithm. Now, the test can inspect the forecasting algorithm and see that it's randomizing. If I ask you what's the probability of rain, you say there's a 25% chance of rain. And then I ask you again, on the same history, what's the probability of rain? And you say there's a 75% chance of rain. Well, now I know for sure that you're not using the true probabilistic process, because you gave me a different answer. You're not even self-consistent.

So a forecaster that is allowed to randomize, we think of as making all of its random choices at day zero and embedding them into the forecasting rule, rather than making them in real time. So this captures things like our online calibration algorithms, which are randomized. It's just that they flip their coins, any coin they're going to need, at the outset. And then they publish a rule that makes predictions as a function of those hard-coded coins. And so when the test inspects them, they appear to be deterministic.

So the premise is that the forecasting algorithm itself might be drawn from a distribution. The test gets to inspect the algorithm, the draw from this distribution, but not the distribution itself.

They can adjust their predictions. There's no reason why the algorithm can't be adaptive. And in fact, even the informed forecaster would be adaptive, because there can be correlations across days. And so what is the correct forecast tomorrow depends on what the outcomes were on previous rounds. It's just that they're not sampling independent randomness at test time. The true informed forecast won't be randomized. And even for things that are able to pass the tests where the algorithm is randomized, they don't need to randomize at test time. There's no difference in observed behavior if I flip coins as I need them, or if I flip them all up front and read them off as I need them. And so the presumption here is that they're flipped all up front and embedded into the algorithm.

So the rule itself is given to the test, the test has full access to it, but the rule is not independently randomizing. So you can't catch a randomized algorithm, for example, just by repeatedly querying the same history and seeing if the forecast is different. Does that make sense?

7An Uninformed Provider Can Pass Reliably

The first theorem that we're going to see is that, as we've set things up, it's impossible to have a test with any non-trivial distinguishing power between an informed forecaster and a completely uninformed forecaster.

What does the theorem say? It says, suppose I've got a test that is guaranteed to have false negative rate at most \(\alpha\), meaning in the worst case over outcome distributions, it fails the informed forecaster on that outcome distribution with probability at most \(\alpha\). So it doesn't make false negative mistakes too frequently. Then it's got to have false positive rate \(1-\alpha\). It has to have zero distinguishing power.

Okay, so it says, for any test that is guaranteed to pass informed forecasters with probability \(1-\alpha\), there is an algorithm that you could design with that test in mind that will also pass that test with probability \(1-\alpha\). And this algorithm doesn't need to know the true underlying process. In fact, this algorithm will pass the test with probability \(1-\alpha\) for every sequence \(y\). Forget not knowing the true underlying process; it doesn't need to depend on there being a true underlying process at all. It'll just be guaranteed to pass the test with probability \(1-\alpha\) for any sequence.

So, at least in the model as we've set it up, this is completely dashing your hopes for being able to audit whether a predictive model knows the true underlying distribution. If you were hoping that this thing would provide useful signal by passing informed forecasters, we're saying, well, no: any test that is guaranteed to pass informed forecasters can be passed at exactly the same rate by an algorithm that knows nothing except the test. The algorithm is going to be tailored to the test, and it'll in fact pass the test with probability \(1-\alpha\) no matter what the sequence is, even on an adversarial sequence.

So whatever you were hoping your complicated test was (and again, this is a very broad class of tests; it can do whatever it wants with your forecasting algorithm itself, it has access to the weights of your model, it can compute whatever statistics it likes relating those to the actual sequence of \(T\) outcomes), it has zero distinguishing power, no matter what the test is, between an informed forecaster and one that is instead designed just to game this particular test.

Does the statement make sense? We'll see the proof; it's actually quite simple, given the technology we've built up. But does the statement make sense? This is, if you want to view it this way, a striking negative result for auditing. Said in contrapositive: if you're going to design a test that will ever fail an uninformed forecaster with non-trivial probability, it has to also have a high false negative rate. There's a setting with an informed forecaster that it also fails.

8How Can the Provider Pass Without Knowing the Law?

Okay. So we already know how to prove this theorem, because we've already developed the technology. This is going to be a consequence of the minimax theorem. Yeah, the minimax theorem is wild. When you state it for rock, paper, scissors, maybe you don't realize [how powerful it is]; this is one of the applications that highlights it. But this is really just a simple application of the minimax theorem.

So the idea is we're just going to write down a zero-sum game between a learner and nature. And the payoff in this game will be determined by the test. The strategy space for the learner is just the set of forecasting rules they can use. The strategy space for nature is just the sequences of outcomes. And once the learner fixes a forecasting rule and once nature fixes a sequence of outcomes, we can apply the test and we can see whether the test passed the learner or not. And if both of them are using mixed strategies, a distribution over forecasting rules and a distribution over outcome sequences, then there's a probability that we pass the test somewhere between 0 and 1.

And the maximization player is the learner. They would like to maximize their probability of passing the test. And the minimization player is nature. They would like to minimize the probability of the learner passing. It's a zero-sum game. We're going to need to verify that we can take the strategy space to be finite, but we will be able to. And because it's a zero-sum game and finite, we know the minimax theorem applies. We've proven it already.

Which means that in analyzing the value of the game, how well the learner can do, you can study either order of play. That's what the minimax theorem says. Order of play does not matter. And the order of play will determine whether the optimal strategy for the learner is to act as an informed forecaster, which we know allows them to pass the test (that's the hypothesis), or whether it requires them to act as a charlatan, to fix a strategy, a distribution over forecasts, that will be tested against the worst possible sequence. And the minimax theorem says those two orders of play are the same. We'll go through the details in a moment, but you should be able to work it out just from this description. This is going to follow just as a consequence of the minimax theorem.

9Why Is This a Finite Game?

So maybe let's first just dot our i's and cross our t's and make sure that the minimax theorem applies. The version of the minimax theorem we've used in class […] applies to any zero-sum game in which the strategy space for both players is finite. Finite doesn't mean small. It can be arbitrarily big, but it needs to be finite.

First of all, what is the set of pure strategies for nature? There are \(T\) rounds; \(T\) is fixed. Remember I said it's important for this result that \(T\) be fixed. It's going to be here that it's important, where we prove that the minimax theorem applies. On each of the \(T\) rounds, the outcome is going to be either 0 or 1. So the set of pure strategies for nature is large but finite.

Now, you might start worrying about the set of pure strategies for the forecaster. The forecaster can map any history onto a real-valued probability, the probability of the event the next day. And if […], this is not finite. Even the number of forecasts I can make today is a continuum. I can predict any real number between zero and one.

But that's okay, because the forecaster cares about the details of their forecasting algorithm only insofar as it affects whether they pass the test or not. And whether they pass the test or not is binary, right? So for every forecaster cross outcome sequence, the test either passes, outputs one, or fails, outputs zero. So you can associate any forecasting algorithm with a vector of \(2^T\) bits, basically, specifying whether this forecasting algorithm passes the test on each of the \(2^T\) possible sequences. And two forecasting algorithms that map to the same bit sequence are identical as far as the learner is concerned. They lead to the same payoff in the game.

So every forecasting algorithm can be identified with a vector of \(2^T\) bits, which means there are merely \(2^{2^T}\) distinct forecasting algorithms. Any two algorithms that lead to the same outcome of the test on all bit sequences can be collapsed into one. And so how many test patterns are there? There are merely \(2^{2^T}\) of them, which is again a big number, but the minimax theorem doesn't care that it's a big number; it's finite.

So this is just to say we can think about this game as being defined by a finite strategy space for both players. There are \(2^T\) distinct strategies for nature, and there are \(2^{2^T}\) distinct strategies for the forecaster. And so it's a finite zero-sum game, and we can apply the minimax theorem. Does that make sense?

Checking this might seem like a technicality, but actually we'll see that this theorem is going to break if we change how the test is allowed to operate by removing the fixed forecasting deadline. If the test can wait an arbitrarily long time before rejecting, this impossibility result is going to go away. And the part of the proof that it's going to break is exactly this. In that case, we'll end up with a game that is not finite, and so we'll break the minimax theorem.

Student: Why do we need to [establish finiteness]?

Roth: Okay, good. So first, why it's important that we establish this. The minimax theorem depends on the strategy space being finite. There are games, like pick-the-bigger-number, for which order of play matters. If you go first, I'm going to be able to win pick-the-bigger-number. But if I go first, you're going to be able to win. So how come that doesn't contradict the minimax theorem? It's because the conditions of the minimax theorem aren't satisfied.

So, a priori, there are continuously many forecasting algorithms. In fact, worse than that, there are continuously many forecasts I can make. But the claim is I can group them into equivalence classes, only finitely many equivalence classes, such that everything within each equivalence class is indistinguishable relative to the game payoff. And so I might as well play the game with one strategy for each equivalence class. This will now be merely finitely many strategies. And because every strategy within each equivalence class is payoff equivalent, this hasn't really changed the game. And the equivalence classes are going to be defined by whether the test produces the same outcome on every single outcome sequence.

Student: So this requires the [test to be known]…

Roth: Well, the test is known. The form of the theorem is: for every test there exists an uninformed, randomized algorithm that can pass it. But it will depend on the test, and the way that will manifest itself is that the algorithm that passes it will be the maximin strategy in this game, whose payoff is determined by the test.

Good. Okay, so we've hopefully convinced ourselves that I can think of this as a finite game, and so I can apply the minimax theorem with my head held high.

10What If the Provider Knew the Outcome Law?

So let's just think about this game in each of the orders of play, which the minimax theorem tells us have the same value. Suppose nature goes first. Nature has to commit to a mixed strategy, to some distribution over outcome sequences. And now the learner is given the opportunity to best respond to that fixed mixed strategy of nature.

In this case, the learner is an informed forecaster. A mixed strategy of nature gives some outcome law, some distribution over outcome sequences, and so in particular gives a true outcome probability conditional on every history. And so one way the learner can best respond if nature has committed first is by acting as an informed forecaster. If nature commits first and tells me their strategy, then I actually do know the underlying physical process that is generating the outcomes. Nature was kind enough to tell it to me.

And I have been promised (it was one of the hypotheses of the theorem) that this test is going to pass an informed forecaster with probability at least \(1-\alpha\), no matter what the underlying distribution is, in particular for this one. 11Minimax Removes the Need to Know the Outcome Law

This observation, that if you know nature's distribution you can always respond as an informed forecaster, one way to write it is as something we have learned about the min-max value of the game. Nature goes first and commits to a fixed strategy, a distribution over sequences, and then the learner gets to best respond by maximizing over the set of forecasting rules, and what they are evaluated on is the probability of passing the test. In this order of play, we've established that the learner passes the test with probability at least \(1-\alpha\). The min-max value of the game is at least \(1-\alpha\).

But we established that this was a finite game, and so we can apply von Neumann's minimax theorem. And the minimax theorem lets us reverse the order of play without changing the value of the game. So applying the minimax theorem, we see that the value of the game is still \(1-\alpha\) if we allow the learner to go first and commit now to a distribution over forecasting rules, and then allow nature to best respond, to pick the sequence of outcomes most likely to cause this learner to fail the test. Even in this order of play, the learner will pass the test with probability at least \(1-\alpha\), because the max-min value of the game is equal to the min-max value of the game. Okay?

And this order of play is the conclusion of the theorem. It says there is a fixed randomized algorithm, a fixed distribution over deterministic forecasting rules, that will pass the test with probability \(1-\alpha\) for every sequence, even in the worst case over sequences. And so in particular, this rule is determined by the test (that's what defined the game), but not determined by the outcome distribution. It [works] for every sequence. So it's uninformed. It didn't need to know the outcome distribution to pass this test, no matter what the test was.

And what is that randomized algorithm? It is exactly the max-min strategy of the zero-sum game. This is non-constructive. It doesn't hand you what the algorithm is. You can try to solve the game, but it's a very big game. But it's establishing that such an algorithm exists, and therefore establishing the limits on what you can conclude through this kind of auditing.

So I think it's a broadly sweeping negative theorem, a surprising statement, but really just an elementary application of the minimax theorem. This is one of the nice, I think, counterintuitive applications of the minimax theorem. Makes sense?

12What Changes If the Audit Has No Deadline?

Okay, so let's try to break the theorem. Let's try, despite this theorem, to come up with a test that has a low false negative rate, that will not fail informed forecasters very frequently, and yet cannot be ignorantly passed, such that there's at least one sequence that fails any uninformed forecaster with high probability.

Now, we have a theorem. So if we're going to come up with a test that is in violation of this theorem, we need to have it operate in some setting that is not covered by the theorem. And the part we are going to relax is the idea that there's this fixed deadline \(T\). The tests that we've considered so far, and for which we've faced an impossibility result, were arbitrary within their scope, but they were restricted to watching the outcome sequence for \(T\) days and then rendering a verdict, accept or reject. \(T\) could have been anything. It could have been a thousand days, a million days. But it was something. It was a fixed deadline. And the fact that it was a fixed deadline actually came up in our proof. When we established that this was in fact a finite game, we used the fact that numbers like \(2^{2^T}\), although possibly very big, were not unbounded.

And so to get a test that has some distinguishing power, what we are going to do is allow there not to be a fixed deadline. The test will be able to monitor the forecaster for an arbitrarily long time before potentially rejecting. In the sequences we construct, it will reject at some finite time for every forecaster it faces. But the time at which it rejects might now depend on the forecaster it faces. That's what's going to give us the power to circumvent this theorem. And the reason why it's going to break the proof of this theorem, which it must do if it's going to contradict it, is that when \(T\) is not fixed, this is no longer a finite game.

19Summary

Just to summarize: if the goal of your audit is to determine whether some forecaster [knows] the underlying probabilistic process governing observations that you can make, and you don't know anything about the world, so you require that the false negative rate be less than \(\alpha\) no matter what the underlying probabilistic process is, then you're kind of out of luck.

And the way around it we saw today was to relax the necessity to reject at some fixed time. But you could imagine other ways around this if you know something about the world. In general, the proof of the impossibility result can guide you towards understanding what you would need to break free of it. The impossibility result was proven via the minimax theorem, so if you're going to break free of it, you need to be in some scenario where the minimax theorem does not apply. That was why we got some mileage out of relaxing this [deadline].

There are other ways to do that. Suppose I knew something about the underlying probabilistic process. Suppose I knew, for example, that it was a product distribution. Maybe I thought there were no correlations across days. Well, that would break the minimax theorem. One requirement of the minimax theorem is that the strategy space for the two players be convex. But product distributions are not convex. Mixtures of two product distributions are no longer a product distribution. I could have two independent sequences, but as soon as I mix between them, they're not independent anymore.

And indeed, it would be very easy to come up with a test that could not be ignorantly passed if I believed that the underlying process was a product distribution. Because an informed forecaster, if the world was a product distribution, would never vary their forecasts. They would make the same prediction every day, and so I could reject if I ever observed you to vary your forecast. That would mean you didn't already know the answer; you were trying to learn it as you go.

And an informed forecaster would also be unbiased. Not only would they make the same prediction every day, they would make a prediction equal to the true underlying probability. And so if I measured the bias of their forecast over time, it would go to zero. But if you're uninformed, there's no way for you to simultaneously satisfy those conditions. You could, of course, learn to be unbiased or even calibrated, but that would require reacting to the observations you've seen and changing your forecast over time. But changing your forecast over time is inconsistent with making the correct forecast in a world in which the correct forecast does not vary with time.

So if I believed that observations came from a product distribution, then I could circumvent the impossibility result. And the reason why the theorem wouldn't apply is because the minimax theorem doesn't apply when the strategy space for nature is the set of product distributions, because it's non-convex. You can imagine other ways to try to circumvent the impossibility result given facts you might know about nature. And just as high-level guidance: facts you know about nature are only going to even potentially be ways to circumvent the impossibility result if these facts somehow break the minimax theorem.
