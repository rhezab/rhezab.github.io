2The Alignment Goal: One Predictor, Many Users

[…] developing essentially this, where we're trying to think of alignment in the sense of aligning a predictor with the goals of downstream decision makers. I want to think about a decision interface where we can have a single model that provides prediction as a service to many different downstream decision makers, each of whom might have their own decision problem. They each might have different collections of actions. They might have different losses they're trying to minimize.

And what we're trying to do is figure out what are the properties of forecasts that we can make that are as agnostic as possible to the particular decision problems the downstream decision makers want to solve, while still being able to provide them with strong guarantees.

3Overview

We've seen a little bit of how to do this previously. In particular, we've seen calibration, which is nice in that it's completely agnostic to the downstream task. The definition of calibration doesn't mention at all actions or loss functions. And yet we saw that if forecasts are calibrated, it promises simultaneously for all downstream decision makers that they can't do any better than to trust the forecasts and act accordingly.

Calibration was kind of hard to obtain except in low-dimensional settings, but we saw a weakening of it called decision calibration that let us still make promises about swap regret to, maybe no longer all downstream decision makers, but any downstream decision maker whose loss function was in a class for which we could promise decision calibration.

Student: So what's the problem? What is not satisfying?

Roth: You're asking why would we want more. There's two things. One is that both of these guarantees are weak in a way that I want to strengthen in this class, and we'll talk about the sense in which they're weak. But the other is that there is still a difference between calibration, which can promise something simultaneously for all downstream decision makers, and this notion of decision calibration, at least as we've defined it: the definition of decision calibration does make reference to the utility function of the downstream decision maker.

Now, we saw last class that you can satisfy decision calibration for many downstream decision makers, but it's not free, in the sense that the computational complexity of running the Blackwell approachability algorithm depends on the dimensionality of this vector, and that's going to grow linearly in the number of decision makers that we stack up. There's also a statistical cost that we didn't talk about quite as much: the regret bounds you get are going to degrade mildly, with the log of the number of decision makers. But if you have infinitely many, the log can still be […]. There are things you can do there. I can offer decision calibration with respect to a covering of the set of all utility functions that can be defined over some action space and still get guarantees for all downstream decision makers. But now the computational advantages over full calibration start to be weaker, at least, because you have to think about how to enumerate […]. Makes sense?

There's another important way in which we might want something stronger. The definition of calibration and decision calibration makes reference only to the sequence of forecasts and outcomes. In particular, it makes no reference at all to the features that might be available in making the prediction. Which on the one hand is a strength: the fact that you can get calibration and decision calibration without needing any special property of the features means you can always do it. On the other hand, the features are generally going to be relevant to good decision making. We want to extract useful signal from the features to aid in downstream decision making.

And the strength of calibration and decision calibration, which is that you can do it in all situations, even if there is no signal in the features, is also a weakness. It means that the kinds of decision-theoretic guarantees that follow merely from calibration and decision calibration are, in some sense, necessarily only self-referential. We promised that there's no way to use calibrated forecasts in a more effective manner than treating them as correct. But you might be able to make better decisions by using information other than the forecasts, because calibrated forecasts might have failed to incorporate decision-relevant information into the forecast itself.

So what we're going to look at today are guarantees of the same sort: we still want to make a single set of predictions that can offer guarantees to many downstream decision makers. But we now want to offer them guarantees that are not merely self-referential, but promise, for example, that trusting our forecasts and acting accordingly will only do better for them than some entire family of policies they could have used that would also be able to make use of the features.

4Recall What Calibration Guarantees

So I just want to start by recalling what calibration and decision calibration are. We've talked about these in higher-dimensional settings, but I want to return today to the simplicity of binary outcomes. So the outcome is either going to be zero or one: the event happens or it doesn't.

And an important part of today's lecture is that there are features available that you can use to make the prediction. So there's going to be some context \(X\) that is available before the prediction that can inform what the prediction is. And a forecaster, given the features \(X\), will make some prediction \(p(X)\) that purports to be the probability that \(Y\) is going to be 1.

As before, we can talk about these things either under a fixed distribution or under the more difficult online adversarial setting. We will see that we can accomplish everything that we set out to do today also in the online adversarial setting, but let's start in the simpler distributional setting.

Just recalling these two definitions from prior lectures: calibration asks that the bias of the forecasts be zero, conditional on the value of the forecast itself. We make some forecast; in this case, since the outcome is binary, the forecast is just a number, like we forecast a 70% chance of the event occurring. Calibration asks that the average of our outcomes equal the average of our forecasts, conditional also on the value of the forecast. So conditional on reporting a 60% chance of rain, it should rain 60% of the time.

Decision calibration asks for something weaker than that. It notes that perhaps, for any forecast in the range between 60% and 100% chance of rain, for example, you might decide that it is a best response to bring an umbrella. And it says, okay, well, given that we only care about making promises about your downstream decision making, we don't need to separately condition on a 72% chance of rain as distinct from a 73% chance of rain. So decision calibration is asking for the weaker condition that our forecast be unbiased, now not conditional on the bit-precision-level details of the forecast, but only conditional on the decision that it induces in you as a decision maker.

The decision that you make as a function of my forecast, your best response action, depends only on my forecast. So if I'm unbiased conditional on the value of the forecast itself, I'm also unbiased conditional on the decision that it induces. That's just some coarsening of the forecast. But the reverse is not true. I can satisfy decision calibration without being fully calibrated.

And the thing I want to point out about these conditions is that the strength of what they are asking can vary as a function of how expressive the forecast is, because the conditioning events are self-referential. If I make perfect predictions, that is going to be calibrated. So calibration doesn't prohibit me from making extremely discriminative predictions. But if I make perfect predictions, then the conditioning event is an extremely stringent constraint. On the other hand, I can also be calibrated in a distributional setting just by making a constant prediction, if I just predict the mean of the distribution.

And why is that the case? Well, it's because the conditioning event becomes vacuous if my forecaster is a constant function. I'm conditioning on the value of the forecast, and if I always forecast a 50% chance of rain, for example, the conditioning event is constant. So this reduces only to asking that the forecast be unbiased, and it is if 50% is the correct average chance of rain. So calibration induces these constraints that can be useful, but somehow there's a way to cheat by coarsening my forecasts until the constraints are no longer binding. Yeah?

5A Constant Mean Forecast Passes Both Tests

Just to observe that you can give a pretty useless forecast while still being calibrated, let's think back to maybe a simpler version of a game we've seen before. We're trying to decide whether to deploy a system that could be either safe or harmful. And say we've got some distribution of proposals, and half of them are safe and half of them are harmful. \(Y = 1\) in this case just means safe. And maybe there's even a way to distinguish them. We have features, and maybe from the features you can figure out whether this is safe or harmful, even deterministically.

Merely asking that the forecast is calibrated does not require that you take advantage of this distinguishing feature, as I think becomes obvious if you think about it for a second, because the definition of calibration doesn't make reference to the features. Tell the same story where there was no distinguishing feature, and you can still be calibrated. So adding the features doesn't break calibration, because the definition of calibration doesn't reference the features.

So suppose I always predict one half. Well, I've ignored the useful information, but I'm still calibrated, because I'm unbiased conditional on the prediction. Because the prediction is constant, being unbiased conditional on the prediction just means being unbiased. And I predicted one half, and indeed half of the proposals are safe. So I'm calibrated.

If I had tried to be more clever and vary my prediction as a function of the context, if there were only two values of the context, that would have forced me to become perfect if I were calibrated. If I distinguished the two informationally distinct contexts with my forecast, calibration would have forced me to make perfect predictions in this case. But I can avoid that by not distinguishing them at all. Calibration lets you cheat by coarsening away information that might be relevant. Because it's calibrated, it's of course also decision calibrated.

6Low Swap Regret Can Be Weak

Now, none of this contradicts the swap regret guarantees that we proved. So just to tie this again to a simplification of the toy decision-making story we had previously: suppose I've got two actions. I can deploy the proposed system or I can hold. And let's say in this case we're writing down loss. Maybe deploying a safe proposal costs me nothing, the loss is zero; deploying a harmful proposal costs me one; and if I hold back, my cost is one quarter in either case. I didn't deploy it, so I don't care whether it's safe or not, but I failed to deploy a useful system.

So what happens under this calibrated but not terribly informative forecast, where I always predict one half? Well, the downstream decision maker can compute their expected loss for deploying: half the time the system is safe, so the expected loss of deploying is one half. And the expected cost of holding is only one quarter. And so, since the forecast is always constant, the best response policy is also constant. It always holds.

Indeed, the downstream decision maker has no swap regret. It's because swap regret kind of has the same self-referential property as calibration. It says there is no way for you to improve your performance, even in hindsight, by consistently replacing any one action by any other action. And this could be a very strong guarantee if you make fine-grained distinctions in terms of what action you play in different situations, because then replacing one action can make fine-grained changes to your behavior. But if you've only ever played one action, if your behavior is constant, then this is just saying there's no way to improve in this case by switching from always hold to always deploy. And indeed, there's not. If you are restricting yourself to a constant strategy, always hold is better than always deploy.

So that's good, but that's the extent to which swap regret is promising you something in this scenario. Swap regret collapses to no more than the promise that you're doing as well as the best single action in hindsight if you never made any distinctions between days, right? Swap regret is only stronger than external regret if you do different things on different days.

Now, the premise here was that there was a feature that does distinguish safe proposals from harmful proposals. And it has expected loss one eighth, which is better than the loss of always hold.

The fact that there was no swap regret, of course, does not promise that you are making the optimal decisions. Again, how could it? Swap regret doesn't even make reference to the context. To evaluate whether you have no swap regret or not, you don't care whether the context was informative.

9One Predictor Serves Many Downstream Users

Good. So let's now set up a slightly more general framework. Suppose we've got a distribution over \((X, Y)\) pairs. \(X\)'s are the features you observe before prediction. \(Y\) is the binary outcome you're trying to forecast. And we'll have a predictor, which is some mapping now between features and forecasts.

And we've got a bunch of different downstream users who have different decision problems. What that means is each user has some action set, which could be different for different users, as well as a loss function. I talked about utilities in previous classes; I'm going to talk about losses here. Maximizing utilities is the same as minimizing the loss that is its negative. A loss is just going to be some mapping from the action that you take and the binary state of the world to a number between 0 and 1.

So just like before, if I knew what the outcome was, or if I knew what a distribution over the outcome was, I could figure out what was my best response action, the action that would minimize my loss. But I don't know what the outcome is. That's why I need to talk to this predictor. And the setup we're going to think about is, again, a common predictor that is ingested by all downstream users. Of course, since they have different loss functions, they will use the predictions differently.

10Each Loss Defines Its Own Best Response

Again, we can think about how a downstream decision maker should act if our forecasts were correct. Our goal is to provide guarantees that they will do well if they trust our forecasts and act accordingly.

Because we've restricted attention to a binary setting, the structure is especially simple. If you knew that the probability of a positive outcome was exactly \(q\), then you could figure out the loss of any action. It would just be \(1 - q\), the probability that the outcome is zero, times the loss you would experience taking that action if the outcome was zero, plus \(q\), the probability the outcome is one, times the loss you would experience if the outcome was one. And your best response action, if you have loss \(\ell\), to a forecast \(q\), or at least to a real probability \(q\), is just the action that minimizes this expected loss.

This is how you should act if the forecasts were correct conditional probabilities. We're not going to be able to promise that we can learn correct conditional probabilities; that's in general impossible. But we would like it to be safe for you to act as if they were.

We're going to now compare the performance of the user to what I'll call policies, which can in general use context and choose actions directly as a function of context, not necessarily using our predictions. But the special policy that doesn't do that, that just best responds to the forecasts we make, I'll just call the best response policy. And the kind of guarantee we'll want to prove is that the best response policy does better than some whole class of other policies. The best response policy of course is parameterized by the loss function. It's different for different decision makers, because they're optimizing a different loss.

11Omniprediction Competes with Contextual Policies

So suppose we've got a family of downstream losses. These are parameterizing the collection of downstream decision makers: they've got a loss function in this family. And now let's say we also have some benchmark class of contextual policies. These are things they could do as an alternative to using our forecasts, that directly look at context and map to actions. You could train your favorite learning algorithm in whatever family or architecture you like that just directly takes as input context and suggests actions. Let's call that a benchmark class. The bigger the better.

Our goal will be to make statements like: don't bother learning over this benchmark class. It's not worth it. You might as well just best respond to our forecasts as if they're correct, and you'll do better than anything in it. And an omnipredictor is a predictor that's going to have exactly that guarantee.

Say that a predictor, a mapping from contexts to forecasts, is an \(\varepsilon\)-omnipredictor for a class of loss functions and a class of benchmark policies if, simultaneously for every loss function, what I can promise is this: if you just don't worry about it and treat our forecasts as if they were the truth, and just compute your best response action, as long as your loss function is within the class \(\mathcal{L}\) that we are making promises about, then I will promise you that your loss, in expectation over this distribution, is no worse, except possibly by \(\varepsilon\), the error parameter, than if you had used the policy in the benchmark class chosen specifically to optimize your loss.

This is true simultaneously for all of these loss functions, even though the policy in this benchmark class that optimizes one loss might be different than the policy that optimizes another loss. So we're simultaneously making promises to people who care about different things, as measured by their loss function, that they're doing better than the best thing in the benchmark class for them, despite the fact that the best thing in the benchmark class for them might be different for different people. Yeah?

11Omniprediction Competes with Contextual Policies

In principle, it is obvious that omnipredictors exist, because the predictor that has learned everything about the distribution and always reports the true conditional probability that \(Y\) is 1, conditional on \(X\), is an omnipredictor. Because if you knew that, then best responding would be pointwise optimal, and so would of course dominate any other policy.

So it is possible to be an omnipredictor. All you need to do is completely learn the true conditional probabilities for every \(x\). The problem is that's generally going to be quite hard. And so the punchline, of course, is that we're going to give omnipredictors under much weaker, tractable conditions. But it is possible.

12Imagine a World in Which the Predictor Is Correct

And as a proof device, I want to imagine a world in which we had actually obtained the dream, and we had actually learned the true conditional distribution. And the way we will model this dream in the hypothetical world is not by changing what our predictor is, but by changing what the world is.

So in this hypothetical world, the labels are drawn according to a different distribution. The label \(\tilde{Y}\), tilde for the hypothetical world, conditional on \(X\), is drawn according to a Bernoulli distribution centered at our prediction. So if we predict a 70% chance of rain, our predictor might have really missed a lot of properties of the world that would have allowed us to make different predictions on different days. But in our hypothetical world, when we predict a 70% chance of rain, God just reaches into his pocket, pulls out a quarter that has bias 70%, flips the coin, and that's the true outcome.

So there's no premise that we've actually learned the true conditional probabilities, but we're going to imagine a world in which our prediction actually determines the generating process for the outcome. The fictional world is not the real world, but we're going to imagine both of them. Both the fictional world and the real world share the same context distribution. So if I want to sample coupled samples from the two worlds, first I will sample context \(x\). Then in the real world, I will sample \(y\) from the unknown distribution of \(Y\) conditional on \(x\). I don't know what that is. It's what the real world does, though. In the fictional world, I will sample \(\tilde{y}\) from the Bernoulli distribution centered at my prediction. My predictor is really, really good in the fictional world.

And the goal of the analysis that we're going to want to do to establish the existence of omnipredictors is essentially to draw two links between the fictional world and the real world. We'll want to say that best responding to the forecast does comparably well in the fictional world and the real world. And we're going to want to say that anything in our benchmark class also does comparably well in the fictional world and the real world. That'll be enough, because the best response is just a terrific policy in the fictional world, because our forecasts were correct.

13Best Response Is Optimal in the Synthetic World

So given some policy \(\pi\), which maps contexts to actions, I want to think about how well \(\pi\) does in the real world and also in the fictional world. So I'll look at the risk under loss \(\ell\) of policy \(\pi\). If I don't draw a tilde over it, that's in the real world: it's just the expected loss of playing this policy under the real context–outcome distribution. And if I draw a tilde over it, and I'll also subscript it with \(p\), my predictor, because the fictional world depends on what my predictor is, I'm just going to look at the same expected risk, but now under the labels drawn in the fictional world. My real risk is \(R\), my fictional risk is \(\tilde{R}\).

And one thing that is straightforward is that best response is just the optimal policy in the fictional world. Best response definitionally takes the action every day that minimizes loss as measured in the fictional world. We make a prediction \(p\), and best response just takes the action that is a loss minimizer in the world in which \(Y\) is sampled from \(p\). So definitionally, best response is pointwise optimal in the fictional world.

The only reason why best response might not be a good idea in general is because our predictions are not in fact the true conditional probabilities. That's the issue. In these simple examples, things were calibrated, but it was exactly because the predictor had coarsened and predicted one half every day, in a way that did not in fact match the true conditional probabilities. But in the fictional world, we've wished that problem away. It's not a problem. Best response is pointwise optimal.

And so in particular, just averaging over the context distribution, it also dominates any other policy, in particular any other policy in our benchmark class. So for every policy, and in particular for policies in our benchmark class, the loss of the best response policy can only be smaller than the loss of the alternative policy, because the best response policy is definitionally the pointwise optimal response in the world in which the forecasts are correct, and that is exactly the fiction that is defining our fictional world. Yep.

14Two Real–Synthetic Comparisons Would Finish the Proof

And so our strategy is going to try to be quite simple. There's one step that's immediate and two steps that we need to prove. But the idea will be to try to step into the fictional world.

We start off by imagining we're playing best response. So here we are playing best response in the real world. I want to say, okay, I can step into the fictional world. I'm still playing best response, but now I'm measuring my risk under the fictional outcomes. And hopefully stepping into the fictional world hasn't cost me more than some \(\alpha\).

Now that I'm in the fictional world, I know that best response is the best thing I can do pointwise. And so within the fictional world, I know that my loss would only be higher if I switched to one of the benchmark policies. That's what we just argued. So this inequality is what we just argued.

Now I'm playing one of the alternative benchmark policies, but I'm in the fictional world. I need to say that playing the alternative policy in the real world is no better than playing best response. So finally, now that I'm playing this alternative policy, I want to step back into the real world, and I want this step back to only cost me some other additive \(\beta\).

So this is the proof strategy. The fact that once we're in the fictional world we can't do better by switching from best response to anything else, that's kind of immediate. That's what we just argued on the last slide; that's the purpose of constructing this fictional world. But to complete this proof strategy, we need to establish the first inequality: that there's some property of the forecasts that makes the best response policy look the same in terms of loss in the real world and the fictional world. And that there's some other property of the forecasts that makes all of the benchmark policies look the same in the real world and the fictional world. And if we have both of those properties, then we can complete this train of thought.

So these are kind of the goals, and these are instantiations of what are called outcome indistinguishability constraints. We want, with respect to some particular test, in this case the test is just computing the expected loss of some policy, that the real distribution and the forecast distribution should look the same. They're allowed to look different in other ways. It doesn't require that we learn exactly the conditional probabilities. But with respect to these particular tests that we care about, these particular expectations, we want them to look the same. Some kind of moment matching. So if we can draw these two arrows, the first one and the last one, between the real world and the fictional world, we'll be done.

15A Binary Loss Is Affine in the Outcome

So let's just do a little bit of algebra that's especially simple, given that we've assumed that the outcomes are binary. Let's say the change in loss I experience at a particular action \(a\), if the outcome changes from 0 to 1, let's call that \(\Delta_\ell(a)\). I'm parameterizing this by the loss function. What's fixed is the action. I'm like, all right, I'm going to bring an umbrella, and what's changing is the outcome. It's how much more loss do I have if it rains compared to if it doesn't rain, given that I'm bringing the umbrella.

And we can just do some simple algebra with binary outcomes. I can write my loss for an action and an outcome \(y\) as just \(1 - y\) times my loss for the action if the outcome is 0, plus \(y\) times my loss for the action if the outcome is 1. And this is just an algebra trick, because if \(y\) is 1, this term is zeroed out, and so it's just the loss when \(y\) is 1; and if \(y\) is 0, this term is zeroed out, and it's just the loss when \(y\) is 0. An algebra trick expressing the correct thing.

But then, just rearranging terms, no matter what the outcome is, I can write my loss as my loss for the action if the outcome is 0, plus \(y\) times the difference between my loss if the outcome is 1 compared to if it's 0. Because if I write down that my loss is whatever it is if the outcome is 0, then if \(y\) is 0, this term is zeroed out. Otherwise, I cross out my mistake and write in the correct value. Which is, in the notation we've given, the loss of the action when the outcome is 0, plus \(y\) times \(\Delta_\ell(a)\), \(y\) times this change.

And if I were in the synthetic world, and I looked at the expectation of this loss conditional on \(x\), because \(\tilde{Y}\) is Bernoulli and \(p(x)\) is fixed given \(x\), I could just write this as the loss of \(a\) if the outcome was 0, plus \(p(x)\) times the change in loss for action \(a\). In the real world, I can't do that, because \(p(X)\) is not the real conditional probability. But in the synthetic world, I can do it, because I know the conditional probability.

16Every Transfer Error Is a Residual Correlation

So remember what we're trying to do with respect to different kinds of policies. We're trying to say we can move between the real world and the synthetic world without changing what the loss is for executing the policy. So let's just look at the difference in loss of any policy, on the one hand in the real world and on the other hand in the synthetic world.

Just write out that expected difference using the identity we just wrote down. It's just the loss for running the policy when the outcome is zero, plus \(Y\) times the change in loss at the action induced by the policy. This is in the real world. In the synthetic world, the same thing: it's the loss of running the policy when the outcome is zero, but in the synthetic world I can replace the \(Y\) with \(p(X)\), times the change in loss running the policy. The loss when the outcome is zero cancels out. That doesn't depend on the underlying distribution.

And all we're left with at the end is this weighted bias term. It's the expectation of \(Y - p(X)\); this is the bias of our predictor. This is the exact same thing we were controlling using calibration earlier. Now it's not just the unweighted bias. It's the bias weighted by this function, which is the change in loss as a function of the action that I play, which is of course a function of the policy.

So if I knew that my residuals were essentially uncorrelated, had no covariance with this weighting term, this change in loss as a function of the policy, that would mean that this expectation was about zero; the two terms are sort of orthogonal to one another. Then that would mean that, to the extent that I care about the loss of this policy \(\pi\), I really don't care if I'm in the real world or the synthetic world. Other quantities might change. This isn't the promise that the two distributions are identical, but it's saying that, as measured by the expected loss of this policy \(\pi\), I cannot distinguish the real world from the synthetic world. We might say that with respect to this loss, the predictions are outcome indistinguishable from the synthetic world.

And so if we want to be able to carry out this kind of three-step argument to argue that some forecaster is an omnipredictor, it would be sufficient to establish the condition that this quantity was about zero for two kinds of policies: the best response policy and each of the benchmark policies. Because what we need is to move from the real world to the synthetic world when we're playing best response policies, and we need once more to move from the synthetic world back to the real world when we're playing a benchmark policy. First claim is going to be that if I want to move from the real world to the synthetic world, or vice versa, when I'm playing the best response policy, actually we don't need a new condition. And because the best response policy is a function only of the value of my forecast, once I condition on the value of my forecast, this is no longer a random variable. This is just a constant. The important property of the best response policy in this argument is that I can condition on the value of the forecast, and that fixes the best response.

So I'm now looking at the expected bias conditional on the value of the forecast. If that was unweighted, then this would just be expected calibration error. Now I'm just weighting it by some constant value, a potentially different constant value for each forecast, but a constant that is always bounded in magnitude by one. So in the worst case, for every forecast for which this bias is positive, the constant is 1, and for every forecast for which the bias is negative, the constant is \(-1\), which would give me exactly the expected magnitude of the bias given the forecast. That would be the calibration error. And other weights will only give me a smaller value.

So this is saying that if I look at the expected loss under any loss function of the best response policy... the only thing we're using about the best response policy here is that it is a function only of the forecast that we are making. If I want to look at the expected difference between the loss of the best response policy in the real and fictional worlds, then all I need for this to be small is for the forecast to be calibrated.

19A Contextual Test Detects the Missing Information

So let's maybe give an example of that. Remember back to our bad example, where we could be calibrated. The example was: instances can either be safe to deploy or not. Half of them are safe. And we had a calibrated but uninformative forecast that always predicted one half. We just argued that the best response policy, which is also a constant, always hold, would transfer between the real and the fictional world. But there was this better policy that deployed safe instances and held unsafe ones. And for that policy, we can compute these differences.

The delta for the deploy action is minus one, because if you deploy and the outcome is one, your loss is zero, but if the outcome is zero, your loss is one, so the difference in those two is minus one. And if you hold, your loss was going to be one quarter independently of what the outcome was, and so this delta function is just zero. It's a constant in that case.

So let's look at this delta function as evaluated on the optimal policy, which deploys exactly on safe instances. The delta function is zero when it holds, and so this delta function as evaluated on the action taken by the optimal policy is just equal to minus one in the event that the policy chooses to deploy, and otherwise is zero.

Now let's look at the quantity we would need to bound to transfer the loss of this policy between the real and the fictional world. Remember, the quantity we need to bound is the expected bias of the forecast as weighted by the delta function evaluated at our policy. But the problem is now that the policy is correlated with whether the outcome is safe or not, even conditional on the forecast, because the forecast is constant.

So half the time, the truth is that the instance is safe, in which case the policy deploys, and so this delta function is equal to minus one. And when this happens, well, our forecast always predicts one half, but the outcome is always one, because it's the perfect policy, so conditional on deploying, the outcome is one. And so the bias conditional on deploying is not zero, it's one half. On the other hand, calibration is relying on that one-half bias canceling out with the minus one-half bias that results on unsafe instances. But on unsafe instances, since our policy is correlated with the outcome even conditional on the forecast, our policy holds, and the delta value is zero. And so the whole term is zeroed out, and it doesn't cancel out.

And so this policy-weighted bias in this case is not zero, despite the fact that the forecast is calibrated. It's minus one quarter. And it's because if we condition on the action taken by the policy, that can break the calibration of our forecast. That's what cannot happen for the best response policy, because conditioning on the action taken by the best response policy merely conditions on the value of the forecast, and calibration already requires that you be unbiased conditional on the value of the forecast.

So what's really going on here is that bounding these terms uniformly would require conditioning on the action of the benchmark policy. And that conditioning event can break calibration if the policy uses information other than the forecast. Does that make sense?

20Multiaccuracy Supplies the Contextual Tests

So there's two transfer steps we need to make in this argument. We need to argue that we can move between the real world and the fictional world when we're playing the best response policy. We saw calibration was sufficient to do that. But we also need to move between the real world and the fictional world when we are playing one of these benchmark policies, and we saw calibration is not sufficient for that. So we need a new condition there. And that condition will be called multiaccuracy.

So fix an arbitrary collection of functions. Maybe we'll call them test functions. They just map contexts to a number between minus one and one. We will say that a forecast is multiaccurate with respect to these test functions if the residuals of the forecast are uncorrelated with the test functions. Or in other words, when I look at the expected bias of the forecast, the difference between the outcome and the forecast itself, as weighted by any one of these test functions, that bias should be zero. And in general, if it's not perfectly zero, we will measure the error as the worst correlation, the largest value over all of the test functions of the test-function-weighted bias, and we'll call that the multiaccuracy error. There should be no way to predict the errors of the predictor, the residuals of the predictor, using one of these test functions.

So maybe the way to think about it is: we're trying to come up with something that in some, although not all, respects causes our forecast to look like the fictional world. It should look like the world in which our forecasts really are correct. Now, in the world in which our forecasts are correct, conditional on the forecast, there is no way to predict the outcome better than random guessing. If I predict a 70% chance of rain, and what that means is that God is about to flip a Bernoulli coin with bias 70%, there's just no way to be correlated with the outcome. There's no remaining signal. If you have any way of finding remaining predictive signal after my prediction, that means that my prediction can't have been correct.

And this is saying, okay, maybe there's some way out there to find signal even conditional on the prediction, but there should be no way to do it with this restricted class of test functions. If you want to certify that my predictions are not truly correct, you need to step outside of this test class. There's no witness inside this test class that my predictions are wrong.

So definitionally, this is kind of what we need, right? Remember, we did this calculation to step between the real world and the fictional world and have the expected loss of our policy be unchanged. What we need is a condition exactly like this: that the weighted bias of our forecaster should be small, as weighted by these delta functions evaluated at the policy we're using. So we could step between the real world and the synthetic world at cost only equal to the multiaccuracy error of the forecaster, where the class of tests is defined by the loss functions we care about and the benchmark class we care about.

What are the tests? They map \(x\) to these delta quantities, these change-in-loss quantities, at the action selected by the benchmark. This is just by definition: we showed that if for these functions the weighted bias was small, we could step between the real world and the synthetic world. The gap we need to control between the real world and the synthetic world, we've kind of just named it. It's the multiaccuracy error with respect to this class of tests.

25The Residual Constraints Are Response Satisfiable

So I'm going to think about this as a Blackwell approachability problem. There's vectors that are generated; I want the average of those vectors to basically approach zero. To establish that, I just need to check, from last lecture, that the set that I want to approach is response satisfiable. Which just means that if the adversary went first and told me what the outcome distribution was, in that case there would be some forecast I could make that would make every coordinate of this vector in expectation zero, or at least very close to zero. And from last class, if I can establish that, then the simple Blackwell approachability algorithm will do the work for me.

So, same issue as last class: in order for this to work, I need to restrict my forecast space to be finite. It can't be infinite, even though there are infinitely many numbers in the interval between 0 and 1. So I need to discretize my forecast space at some granularity \(\eta\). I can't predict arbitrary reals. I can predict a 0% chance of rain, an \(\eta\) chance of rain, a \(2\eta\) chance of rain, up through 1. There's going to be \(1/\eta\) forecast values, but I don't have any dependence in the bound on how small \(\eta\) is, so you can think of \(\eta\) as being really small.

And I need to define what this vector of outcomes is going to be as a function of my forecast and as a function of the outcome. And that can be different for different contexts. So for a set of test functions, the \(j\)th coordinate of this Blackwell outcome vector, when the context is \(x\), my forecast is \(p\), and the outcome is \(y\), is just going to be the weighted bias increment: the difference between the outcome and my forecast, as weighted by this test function. There's going to be \(m\) of these coordinates.

And the set that I want to approach: really I want to approach 0, but I'm going to approach a slightly larger set, in which the average vector is allowed to have magnitude up to \(\eta\), because of this discretization. So the set I want to approach is just the set of vectors whose coordinates have magnitude at most \(\eta\). These are really small vectors.

And to establish response satisfiability, I get to pretend that the adversary went first. So if the adversary tells me, look, it's going to rain with probability \(q\), then what I'd love to do is forecast probability \(q\) in response, a \(q\) percent chance of rain. I might not be able to do that, because I've restricted myself to this grid, but it's an \(\eta\) grid, so I can always respond with some forecast that, even if it's not exactly right, is correct up to plus or minus \(\eta\). If I do that, and I look at the expected value of the resulting vector in any coordinate, it is bounded by the magnitude of the test function, at most one, times the error, the difference between my forecast and the expected outcome, which is at most \(\eta\). So I can guarantee that every coordinate is bounded by \(\eta\), which means that in this Blackwell game, the set that I want to approach is response satisfiable.

So we already have an algorithm. It's the algorithm from last class, which for any set of test functions can guarantee that the average realized value of this vector, which is, as we've defined it, the average test-function-weighted bias of my forecaster, approaches zero with respect to all of these weighting functions as \(T\) grows large.
